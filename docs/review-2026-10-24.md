## 结论

框架骨架没问题：守卫链顺序、权限缓存的版本号防脏写、JWT 算法限制、日志异步写和滚动清理、路由懒加载、删除二次确认都做得对。问题集中在三块：

1. **授权边界**：后端只校验「有没有这个权限码」，不校验「授出去的权限是否超出自己的范围」，有用户管理权限就能把自己提成超管；前端角色编辑还有一个会悄悄多授权的 bug。
2. **登录态生命周期**：refresh token 轮换没有原子性，加上前端多 tab 各自刷新，正常用户会被当成 token 重放、全端踢下线；改密后旧 accessToken 仍有效；强制改密只在前端拦。
3. **文件模块**：下载功能目前根本用不了；下载流出错会打挂进程；上传先整个读进内存再校验大小。

## 中

**认证与会话**

- **M1 改密/重置密码后旧 accessToken 仍有效**：JWT 校验只看签名和用户状态（`jwt.strategy.ts:40-47`），改密后被盗的 token 还能用最多 2 小时；`resetPassword` 也没调 `permCache.invalidateUser`。
- **M2 强制改密只在前端拦**：`mustChangePassword` 只返回给前端，服务端不拦截，直接调接口可绕过。
- **M3 权限守卫默认放行**（已核实 `permissions.guard.ts:18`）：没加 `@RequirePermissions` 的接口所有登录用户都能访问，新接口忘加装饰器就是越权口子；`'SUPER_ADMIN'` 字符串在 5 处各自硬编码。
- **M4 前端刷新失败一律踢登录**：refresh 用的裸 axios 无超时；断网、超时、5xx 都 `clearAuth()`；路由守卫加载用户信息出任何错也直接登出（`router/index.ts:56-65`）——后端发版重启时在线用户会被批量踢出。
- **M5 登出请求会先触发一次轮换**：logout 走带拦截器的实例，accessToken 过期时先刷新、再拿旧 refreshToken 去登出，可能被判重放。
- **M6 没有跨 tab 登录态同步**：tab A 换账号登录，tab B 界面还是旧用户，请求却带新 token。

**接口与数据**

- **M7 `sort` 参数允许任意字段**（`paginate.ts:7-17`）：不存在的字段触发 Prisma 校验错误变 500；用户列表能 `sort=password:asc`。
- **M8 `TRUST_PROXY` 默认 1**：服务若不经 Nginx 直接对外，`X-Forwarded-For` 可伪造，IP 白名单、限流、登录锁定、审计 IP 都失效。
- **M9 公开的前端日志上报接口可刷满磁盘**：`@Public()` + 按 IP 30 次/分钟，日志文件无单日大小上限；而且因为是 Public，`userId` 永远拿不到。
- **M10 操作日志脱敏不完整**：超过 3 层的对象原样写入（深层 password 不脱敏）；键名精确匹配，漏 `confirmPassword`、`secret`、`captchaCode` 等；系统参数的 value 明文入日志。
- **M11 `/auth/menus` 不过滤已禁用角色**（`auth.service.ts:199-205`）：角色禁用后菜单仍显示，点进去 403。
- **M12 角色编辑只回显叶子节点**：「有页面、没授权任何按钮」的菜单不会被勾上，编辑保存一次就丢了这个页面的权限。
- **M13 上传类型只信客户端 mime**：扩展名黑名单不全（`.html/.svg` 可传），下载时原样回放客户端声明的 Content-Type。
- **M14 软删除文件永不清理**（已核实：`FileService.purge()` 全仓库零调用）：上传目录只增不减。

**任务调度（多实例才会触发，当前单机部署不受影响）**

- **M15**：暂停/删除任务只改本进程调度，其他实例照跑；`run()` 不检查 `status === 'ENABLED'`。
- **M16**：启动时同步补跑错过的任务会阻塞监听端口（最长 `timeoutSec`）；先写库再注册 cron，cron 语法不兼容时库与调度不一致；库里一条非法 cron 会让整个应用启动失败。

**前端交互**

- **M17 写操作普遍没防重复提交**：用户/角色/菜单/任务保存、任务「立即执行」（连点会真的执行多次）、修改密码（第二次必然报错）。
- **M18 编辑时整行数据原样提交**：`Object.assign(form, row)` 后提交整个 form，残留字段可能被白名单校验拒绝（与之前「新增角色失败」同类问题）。
- **M19 取消弹框和业务 4xx 都被当成未处理异常上报**，前端日志全是噪音。
- **M20 图标全量注册**（`main.ts:15-17`）：约 300 个图标进入口 chunk。

## 低

- 多处 `logger.warn(fields, msg)` 参数顺序用反，告警日志 msg 为空（`log-alert.job.ts`、`config.service.ts`、`login-guard.service.ts`、`health.controller.ts`）
- 「最后一个超管」检查在事务外，两人同时互相禁用可能两个都成功
- 软删除用户的用户名无法复用；角色用户数把已删除用户也算进去，导致角色删不掉
- `RefreshToken.expiresAt/revokedAt`、`Notice` 列表查询缺索引
- 上传先写盘后入库，入库失败留孤儿文件；Notice 日期字段只校验 `@IsString()`
- 访问日志记录完整 query；下载的 ETag 没实现 304 协商，设了等于没设
- `assertPasswordUsable` 用同步 `bcrypt.compareSync` 阻塞事件循环
- 验证码 SVG 用 `v-html`（建议改 `<img src="data:image/svg+xml...">`）；token 全放 localStorage
- 侧边栏只渲染两级菜单；chunk 加载失败的刷新标记从不清除；列表请求无竞态保护（快速翻页可能显示旧结果）
- 前端各处密码规则不一致（6 位 / 8 位 / 复杂度）
- 「复制链接」复制出的地址不带 token，打开就是 401

## 核实后没问题的

权限缓存的版本号防脏写与多实例广播；JWT 只接受 HS 算法、不接受 `none`；cron 回调有 catch 兜底，单个任务报错不会停调度；日志下载严格校验日期、无路径穿越；上传文件名 UUID 重命名、无路径穿越；`enableShutdownHooks` 优雅退出；动态路由注册时序、`resetDynamicRoutes` 清理完整；路由全部懒加载；所有删除都有二次确认；公告内容用插值渲染，无 XSS。

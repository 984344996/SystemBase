## 讲解：Nginx 原理 / 可配置项 / 替代方案评估（无代码改动）

- 架构结论：本项目（单机 + PM2 + 软链多版本发布 + SPA/API 同域 + 子路径共享域名 + certbot 自动续期）继续用 Nginx 最务实，不换 Caddy/Traefik/Envoy/云 LB；真正演进时机是「多机或容器化」时再上云 LB + Traefik/Caddy，或把静态资源交给 CDN
- 项目关键配置事实：`deploy/server/nginx-site.conf`（server 块壳）+ `nginx-locations.conf`（路由片段，含三个 location）+ `nginx-setup.sh`（占位符替换、共享域名 awk 注入、nginx -t 失败自动还原）；`setup-ssl.sh` 用 certbot --nginx
- 两个核心原理点：`proxy_pass http://127.0.0.1:__PORT__/api/;` 带 URI 才会剥掉 SITE_PATH 前缀；用 `alias` 而非 `root` 是因为片段会被 include 进别的 server 块
- Nginx `systemctl reload` + `current` 软链原子切换 = 零停机发版；`X-Forwarded-*` 需后端 TRUST_PROXY=1 才认，默认 false 防伪造

## 讲解：Nginx 配置不当的安全风险（无代码改动）

- 发现的真实缺口（待修，未动代码）：前端 HTML/静态资源由 Nginx 直发，helmet 只覆盖 API，所以页面缺 CSP、HSTS、Permissions-Policy；且三个 location 内已有 `add_header`，按 Nginx 继承规则**不会继承** server 级新增的 add_header —— 以后补安全头必须写进每个 location 或用 include 片段，写在 server 块里会静默失效
- 其余待补：网关层无 limit_req/limit_conn（后端 Throttler 依赖 req.ip 且请求已进 Node、单进程内存不共享）；无 `location ~ /\. { deny all; }` 兜底；certbot --nginx --redirect 默认不加 HSTS
- 已做对的点：alias 只读 `apps/web/dist`（`.env`/`prisma`/`uploads` 都不在静态根下）；uploads 走后端鉴权下载未挂静态；proxy_pass 用硬编码常量而非变量拼接（避免 CRLF/走私）；用 `$host` 而非 `$http_host`；location 都带尾斜杠 + alias 带尾斜杠（避免经典 alias 穿越）；server_tokens off；nginx -t 失败自动还原
- 关键认知：`nginx -t` 只校验语法，不校验安全语义；TRUST_PROXY 双向配错都出事（过大=伪造 XFF 绕过 IP 白名单/限流，过小/不配=req.ip 全为 127.0.0.1 导致限流与审计失真）

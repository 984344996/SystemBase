## 修复：发布包带 macOS 扩展属性导致服务器 tar 刷屏警告
- 现象：解压时 `Ignoring unknown extended header keyword 'LIBARCHIVE.xattr.com.apple.provenance'`，无害（文件正常解压）
- 根因：deploy.sh pack() 用 `tar --help | grep --no-xattrs` 检测，但 macOS bsdtar 3.5 的 --help 不列该选项，检测恒失败（旧脚本同样存在）；COPYFILE_DISABLE=1 只管 ._* 文件，不管 xattr
- 修复：逐个实测 `tar --no-xattrs/--no-mac-metadata -cf /dev/null /dev/null` 支持即加；实测发布包 xattr 头 2→0

## Nginx 已有配置会不会被覆盖：分析 + 修复

- 修复：disable_default_site 只在默认站点监听同一 SITE_PORT 时才停用，含真实域名/证书的保留只提示，普通文件移到 /etc/nginx/sb-disabled/<名>.<时间>，nginx -t 失败放回；nginx.conf 只在 SITE_PORT=80 且 SITE_DOMAIN 为空时改，备份 nginx.conf.sb-orig；4 种场景本地验证通过
- 预发服务器实况（只读检查）：OpenCloudOS，conf.d 只有 systembase-pre.conf（8080）+ washsystem.conf（beautywash.top，443 certbot + 80 跳转），washsystem.conf 内容完好，只多了一行带 `# managed by systembase(systembase-pre)` 的 include；该发行版 nginx 包本身不带 conf.d/default.conf（没丢东西）；nginx.conf 的 default_server 已被旧 init 去掉（无原始备份，nginx.conf.default 是 rpm 自带模板可参照），影响仅为 IP 直接访问 80 端口的落点；remote-release 尚未在该机部署（snippets 只有 pre）

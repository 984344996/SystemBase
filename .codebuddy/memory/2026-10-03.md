## 关键结论（后续别再踩）

- **shell 脚本中 `$变量` 后紧跟中文/全角字符必须写 `${变量}`**：用户终端环境曾因此触发 unbound variable，导致 start-local.sh 在启动前端前崩溃、前后端都起不来（表现是「登录不跳转」）。三个脚本已全部修复。
- **Pinia getter 不能读 localStorage**（非响应式、computed 永久缓存旧值）：曾导致登录后 isLoggedIn 恒 false、被路由守卫弹回登录页。已改为 state.token 镜像。
- 新增 Nest provider 若被其他 module 注入，必须放进 `@Global()` 模块（MetricsService 曾因只在 AppModule providers 导致 JobModule 注入失败、服务起不来）。
- Prisma 迁移：改 schema.prisma → `make db-migrate name=xxx` 自动生成 SQL 迁移文件，**不需要手写 SQL**（用户问过）。
- 前端没有落盘日志：只有 request.ts 的 5xx console.error 与 permission.ts 的 console.warn；用户可见错误走 ElMessage。排查靠 traceId 反查后端日志。

## 同机多环境部署（用户提问后修复的真实缺陷）

- 后端端口 `PORT` 可在 env 配置；同机部署预发+正式必须不同（模板已改：pre 3001 / release 3000）
- **原 Nginx 模板写死 `listen 80; server_name _`**：同机装两个环境时 Nginx 报 conflicting server name，**后装站点被忽略**。已改为占位符 `__LISTEN__` / `__SERVER_NAME__`，由 env 的 `SITE_PORT`（默认 80）、`SITE_DOMAIN`（默认 `_`）填充
- **原 `ops.sh stop` 执行 `systemctl stop nginx`**：同机会把另一环境一起停掉。已改为站点级启停（摘/挂本环境站点配置 + reload），新增 site_enable / site_disable
- 同机部署还需互不相同：DEPLOY_DIR、APP_NAME、DATABASE_URL 库名；UPLOAD_DIR 建议设为 shared 下的绝对路径（相对路径会随 release 切换丢失）

## 前端日志上报（用户要求，已实现）

- 决策：**独立文件 web.YYYY-MM-DD.log，与后端 app.*.log 分开**，靠 traceId 串联。理由：前端错误会被每个浏览器重复上报，混入后端会淹没 ERROR 并使告警失真
- 后端：`ClientLogService`（core/logger）+ `POST /api/logs/client`（Public、限流 30/分钟/IP、URL 去 query 脱敏、内容截断、CLIENT_LOG_ENABLED 开关）；LogReaderService/MonitorService 新增 `source=server|client`，下载同步支持
- 前端：`utils/clientLog.ts` 捕获 onerror / unhandledrejection / Vue errorHandler；只报 error|warn、同类 60s 去重、每分钟 ≤10 条、失败静默；request.ts 回填最近 traceId
- 管理端：系统日志页顶部切换「后端日志 / 前端日志」，权限复用 system:log:list / download
